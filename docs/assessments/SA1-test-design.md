# SA1 — Test Design from Requirements

> **หลัง Level 1 (M01–M04)** · ⏱ 3 ชั่วโมง · เอกสารล้วน ไม่ต้องเขียนโค้ด · AI assistant: ห้ามใช้ · ผ่าน ≥ 70/100

## สถานการณ์
ShopLab จะออก release ที่มีระบบคูปอง การเก็บเงินปลายทาง (COD) และการจำกัดอายุผู้สมัคร คุณเป็น QA คนเดียวของทีม มีเวลา 3 ชั่วโมงเตรียมชุดทดสอบให้ทีมใช้ และ **ShopLab ที่ผู้สอนเปิดให้มีบั๊กฝังอยู่หนึ่งตัว** ที่คุณต้องหาให้เจอ

แหล่งข้อมูลเดียวที่ใช้ได้คือ [REQUIREMENTS.md](../../practice-app/REQUIREMENTS.md) และตัวเว็บที่ผู้สอนเปิดให้ (URL จากผู้สอน)

## งานที่ต้องส่ง (ไฟล์เดียว `SA1-<ชื่อ>.md` หรือ `.xlsx`)

### T1 — Equivalence Partitioning + BVA (25 คะแนน)
สำหรับ **REQ-REG-01** (username), **REQ-REG-03** (password), **REQ-REG-06** (phone) และ **REQ-REG-07** (อายุ)
- ตาราง: `Field | Partition (valid/invalid) | ค่าตัวแทน | Expected` อย่างน้อย **20 แถว**
- BVA แบบ **2-value** ของทุกช่วงตัวเลข/ความยาว และแบบ **3-value** สำหรับอายุ
- อธิบาย (2–3 บรรทัด) ว่าจะสร้างวันเกิดสำหรับอายุ 17 / 18 / 60 / 61 อย่างไรให้ test ไม่เสียเมื่อเวลาผ่านไป

### T2 — Decision Table ราคา (25 คะแนน)
สำหรับ **REQ-PRC-02, 03, 04, 05**
- ตารางเงื่อนไข × ผลลัพธ์ ที่ **ยุบแล้ว** อย่างน้อย **6 rules**
- ทุก rule มีข้อมูลทดสอบจริง (SKU + จำนวน + คูปอง + วิธีส่ง) และค่าคาดหวัง **subtotal / discount / shipping / VAT / total** ที่คำนวณถูกถึงทศนิยม 2 ตำแหน่ง
- ระบุ 1 rule ที่ requirement **ไม่ชัดเจน** พร้อมคำถามที่จะถาม PO

### T3 — State Transition ของ order (20 คะแนน)
สำหรับ **REQ-ORD-05**
- state diagram (วาดด้วยมือ/ข้อความก็ได้) + **state table ครบ 5×5**
- รายการ test สำหรับ **0-switch coverage** (ทุก transition ที่ถูกต้อง) และ **ทุก invalid transition** พร้อมผลที่คาด (HTTP status / ข้อความ)

### T4 — Risk-based priority (15 คะแนน)
- ความเสี่ยง **5 ข้อ** ของ release นี้: `ความเสี่ยง | Likelihood | Impact | ระดับ | ทดสอบที่ชั้นใด (unit/API/UI) | เหตุผล`
- เลือก **10 test case** จาก T1–T3 ที่จะ automate ก่อน พร้อมเหตุผล 1 บรรทัดต่อข้อ

### T5 — หาบั๊กและเขียน bug report (15 คะแนน)
- ทำ exploratory session (≤ 45 นาที) บนเว็บของผู้สอน ด้วย charter ที่เขียนเอง 1 ข้อ
- เขียน **bug report 1 ฉบับ** ตาม [template](../templates/bug-report-template.md) สำหรับบั๊กที่ฝังไว้ (ถ้าพบมากกว่า 1 อาการ ให้เลือกอาการที่ร้ายแรงที่สุด)

## Rubric

| ข้อ | ดีเยี่ยม (100%) | ผ่าน (70%) | ต้องปรับปรุง (≤ 40%) |
|---|---|---|---|
| T1 | ครบ 4 field, partition ถูกทั้งหมด, BVA ถูกทุกขอบ, วิธีสร้างวันเกิดแบบ dynamic | ผิด ≤ 3 แถว หรือขาด 3-value | ขาด field / BVA ผิดหลักการ |
| T2 | ยุบถูก, ค่าเงินถูกทุกช่อง, คำถามถึง PO มีเหตุผล | ค่าเงินผิด ≤ 2 ช่อง | ไม่ยุบ / ค่าเงินผิดหลายช่อง |
| T3 | ตารางครบ, 0-switch ครบ, invalid ครบ พร้อม 409 | ขาด invalid ≤ 3 คู่ | ขาด state / ไม่มี invalid |
| T4 | ความเสี่ยงชัด ผูกกับ requirement, ชั้นทดสอบเหมาะสม | เหตุผลบางข้อกว้างเกินไป | เป็นรายการทั่วไปไม่ผูกกับระบบ |
| T5 | ทำซ้ำได้ใน 2 นาที, expected อ้าง REQ, หลักฐานครบ, severity/priority สมเหตุสมผล | ขาดหลักฐาน 1 อย่าง | ทำซ้ำไม่ได้ / ไม่ใช่บั๊กที่ฝังไว้ |

**เงื่อนไขบังคับ:** T5 ต้องเป็นบั๊กที่ผู้สอนฝังไว้จริง (ถ้าไม่พบ T5 ได้สูงสุด 5 คะแนนจาก charter + session notes)
