## C. สิ่งที่ลูกค้าต้องเตรียม

- [ ] บัญชีทดสอบอย่างน้อย **2 บัญชีต่อ role** (เช่น user A, user B, admin) — ใช้ตรวจว่าเห็นข้อมูลของกันและกันไม่ได้
- [ ] ระบบชำระเงินอยู่ใน **test mode** (เช่น Stripe test key) หรือแจ้งว่าห้ามกดจ่าย
- [ ] ข้อมูลตัวอย่างในระบบ (สินค้า, คิว, บทความ)
- [ ] ความต้องการทางธุรกิจที่มี (prompt ที่ใช้สร้างเว็บ, เอกสาร, ภาพหน้าจอที่คาดหวัง) — ใช้เป็น "ผลที่คาด" (expected result)
- [ ] ปัญหาที่รู้อยู่แล้ว (known issues) เพื่อไม่ต้องรายงานซ้ำ

## D. การอนุญาตและข้อมูล (บังคับ)

- [ ] ลูกค้ายืนยันเป็นลายลักษณ์อักษรว่าเป็นเจ้าของหรือมีสิทธิ์ในระบบนี้ และ **อนุญาตให้ทดสอบ** รวมถึงสแกนความปลอดภัยแบบ passive (ไม่โจมตี)
- [ ] ระบุว่ามีข้อมูลส่วนบุคคลจริงในระบบหรือไม่ ☐ ไม่มี (ข้อมูลทดสอบล้วน) ☐ มี → ตกลงวิธีจัดการก่อนเริ่ม
- [ ] ตกลง NDA / การเก็บรักษาข้อมูล (ลบบัญชีทดสอบ, ภาพหน้าจอ, trace หลังส่งงาน ___ วัน)
- [ ] ยอมรับข้อสงวน: เป็นการตรวจสอบตามขอบเขตและเวลาที่ตกลง **ไม่ใช่การรับประกันว่าไม่มีข้อบกพร่อง**
