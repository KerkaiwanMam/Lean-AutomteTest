# รายการข้อบกพร่อง (Findings)

> **เทมเพลต 07** · 1 finding = 1 ปัญหา · เขียนให้ developer (หรือคนที่สั่ง AI แก้) ทำซ้ำได้โดยไม่ต้องถามกลับ
> ใช้ไฟล์นี้ตรงๆ หรือคัดลอกแต่ละ finding เป็น GitHub Issue / แถวใน Google Sheets

## นิยามความรุนแรง (Severity)

| ระดับ | ความหมาย | ตัวอย่าง |
|---|---|---|
| **Critical** | เสียเงิน ข้อมูลรั่ว/เสียหาย หรือ flow หลักใช้ไม่ได้ ไม่มีทางเลี่ยง | จ่ายเงินแล้วไม่มีคำสั่งซื้อ, secret key หลุด, เห็นข้อมูลคนอื่นทั้งหมด |
| **High** | Flow สำคัญพังในบางกรณี หรือปัญหาความปลอดภัยที่ต้องมีเงื่อนไข | จองซ้ำได้เมื่อส่ง request ตรง, Safari กดปุ่มชำระเงินไม่ได้ |
| **Medium** | ใช้งานได้แต่สับสน เสียประสบการณ์ หรือผิดมาตรฐานที่ควรมี | error ไม่บอกว่าผิดอะไร, ขาด security header, axe serious |
| **Low** | ความสวยงาม ข้อความ รายละเอียดเล็กน้อย | ตัวสะกดผิด, ระยะห่างไม่เท่ากัน |

*Severity = ผลกระทบต่อธุรกิจ · ลำดับการแก้ (priority) ให้ลูกค้าตัดสินเอง แต่ผู้ทดสอบเสนอได้*

## F-01 · จองช่วงเวลาเดียวกันซ้ำได้เมื่อส่ง request ตรง

| | |
|---|---|
| **Severity** | Critical |
| **พื้นที่ / TC** | จองคิว · TC-02 (SC-02, R-01) |
| **สภาพแวดล้อม** | `https://staging.example.com` · Chrome 131 Windows 11 · build `abc1234` · 2026-12-01 14:20 |
| **บัญชี** | customer.b@test.local |
| **สถานะ** | Open |

**ขั้นตอนทำซ้ำ**
1. ล็อกอินเป็น customer.a แล้วจองวัน 3 ธ.ค. เวลา 10:00 (สำเร็จ)
2. ล็อกอินเป็น customer.b เปิด `/booking` — ช่อง 10:00 แสดงเป็นไม่ว่าง (ถูกต้อง)
3. ส่ง request เดียวกับขั้นที่ 1 ผ่าน Postman ด้วย token ของ customer.b: `POST /rest/v1/bookings` body `{"slot":"2026-12-03T10:00"}`

**ผลที่คาด:** server ปฏิเสธ (409/400) และไม่สร้างการจอง
**ผลจริง:** server ตอบ `201` และสร้างการจอง `BK-0007` ช่วงเวลาเดียวกับ `BK-0006`

**หลักฐาน:** `video/F-01.mp4` · response body (ปิดข้อมูลส่วนตัวแล้ว) · Playwright trace `trace/TC-02.zip`

**ผลกระทบ:** ลูกค้าสองคนมาพร้อมกัน ร้านต้องยกเลิกหนึ่งคน · ผู้ใช้ทั่วไปทำได้ด้วยการกดซ้ำเร็วๆ หรือสองคนกดพร้อมกัน (TC-03)

**แนวทางแก้ (ข้อเสนอ):** ตรวจช่วงเวลาซ้ำที่ฝั่ง server/ฐานข้อมูล ไม่ใช่แค่ฝั่ง UI — เช่น unique constraint บน (`slot`, `staff_id`) หรือ transaction ที่ตรวจก่อนบันทึก
**Prompt สำหรับสั่ง AI แก้ (ถ้าลูกค้าใช้ AI builder):**
> "Add a database-level unique constraint so that one time slot can only have one active booking. The API must return HTTP 409 with the message 'ช่วงเวลานี้ถูกจองแล้ว' when the slot is taken. Do not rely on the UI check only."

### เคล็ดลับเขียน finding ให้เร็ว
- ชื่อ = **อาการ + เงื่อนไข** ("…เมื่อ…") ไม่ใช่ "ระบบจองมีปัญหา"
- 1 ขั้นตอน = 1 การกระทำ · ใส่ค่าที่พิมพ์จริง
- ผลจริงต้องเป็นสิ่งที่เห็น ไม่ใช่การเดาสาเหตุ (สาเหตุใส่ใน "แนวทางแก้")
- ปิดข้อมูลส่วนบุคคล token และ key ในภาพหน้าจอ/วิดีโอก่อนส่ง
